网页资产计
本地实现方案

以 Chrome Manifest V3 扩展为载体：在 Service Worker 中编排导航事件，在内容侧与性能 API 采集四项指标， 用纯函数公式引擎结算单笔 ≤ ¥10 的入账，全部写入本地 storage，Popup 以账本摘要呈现。

运行时 MV3 Service Worker UI Popup + Options 公式 纯函数可单测 边界 无服务端
01

目标与范围

技术方案必须可直接对照 PRD 验收，而不是另起一套叙事。

做

  • 有效网页识别、URL 规范化、短时去重
  • 四指标采样：停留、加载、新鲜度、页面类型
  • 权重公式结算 + ±8% Noise，clamp 到 0.30～10.00
  • 今日/累计资产、最近 N 笔流水、成就阈值提示
  • 本地重置、目标模板（储蓄 / 克制 / 行动）

不做（MVP）

  • 真实支付、提现、银行对接
  • 跨设备同步、账号体系
  • 用户自定义权重（配置项预留，UI 隐藏）
  • 页面正文/DOM 内容分析、截图 OCR
  • 排行榜与社交分享
02

整体架构

三层：采集层 → 结算层 → 展示层；核心状态只存在 chrome.storage.local。

采集层 Visit Probe

webNavigation + tabs + PerformanceTiming / Navigation Timing；判断是否可计入。

结算层 Ledger Engine

公式纯函数 + 去重 + 新鲜度缓存 + 成就阈值检测；写流水与汇总。

展示层 Popup / Options

账本摘要、最近一笔可解释原因、目标与重置；低打扰、无复杂表格。

03

入账流水线

一次有效打开从导航到落账的完整路径。

1

导航完成

webNavigation.onCompleted 或 tabs.onUpdated（status=complete）。过滤 chrome://、edge://、about:、扩展页、devtools。

2

规范化与去重

去掉 hash、追踪参数（utm_* 等），得到 canonicalUrl。若与 recentVisits 中同 URL 间隔 < dedupeWindow（建议 90s），则丢弃。

3

开启会话采样

记录 tabId、startAt、loadMs（Navigation Timing 或 fallback）。新鲜度查今日域名/路径访问表；类型分由 URL 启发算出。

4

结算触发

优先级：tab 关闭 / 导航离开 / 文档隐藏且累计可见停留达上限（建议 180s 封顶采样）/ 用户切到其他站点。取最终 dwellMs。

5

公式入账

metrics → Score → deposit；追加 ledger 条目；更新今日/累计；若跨越成就阈值，写入 pendingAchievement。

6

展示刷新

badge 可选显示今日入账整数部分；Popup 打开时读 storage 渲染摘要与「最近一笔原因」。

04

公式引擎

必须是无副作用纯函数，便于单测与回归；Noise 注入点显式传入 RNG。

常量（对齐 PRD）

CAP10.00
MIN0.30
权重dwell 0.45 · load 0.20 · fresh 0.20 · type 0.15
NoiseUniform(−0.08, +0.08)
精度两位小数，银行家舍入或 half-up 需固定一种
接口约定

computeDeposit(scores, noise) → { score, raw, deposit, reason }
reason 用于 Popup：「停留 28s · 加载正常 · 新域名」。随机只影响 deposit，不影响 reason 文案主因排序。 

// core/formula.ts（示意）
export function computeDeposit(s: Scores, noise: number): DepositResult {
  const score =
    0.45 * s.dwell + 0.20 * s.load + 0.20 * s.fresh + 0.15 * s.type;
  const raw = CAP * score * (1 + clamp(noise, -0.08, 0.08));
  const deposit = round2(clamp(raw, MIN, CAP));
  return { score, raw, deposit, reason: buildReason(s) };
}

归一化实现要点

  • dwell：分段线性插值，与 PRD 阈值一致（3 / 15 / 60s）
  • load：<200ms 降权；200ms–2.5s 甜点；>8s 低分
  • fresh：今日 eTLD+1 首次 / 同域新路径 / 旧路径三档
  • type：正则启发（/search、/list、query 页降权）；默认 0.60

停留计量

  • 优先用 Page Visibility：仅累计 visible 时间
  • 后台标签不继续涨停留，避免虚高入账
  • 休眠唤醒后用 timestamp 差做上限裁剪
  • content script 心跳可选；无权限页则仅用 tab 事件估算
05

数据模型

全部落在 chrome.storage.local；键少、可重置、可导出（后续）。

type LedgerEntry = {
  id: string;              // uuid
  ts: number;              // 结算时间
  url: string;             // canonical，可只存 host+path
  host: string;
  amount: number;          // 0.30–10.00
  score: number;
  metrics: {
    dwellMs: number; loadMs: number;
    dwell: number; load: number; fresh: number; type: number;
  };
  reason: string;          // 展示用短句
};

type AppState = {
  schemaVersion: 1;
  dayKey: string;          // YYYY-MM-DD 本地时区
  todayVisits: number;
  todayAsset: number;
  totalVisits: number;
  totalAsset: number;
  recentEntries: LedgerEntry[];   // 最多 50
  recentVisitMap: Record<string, number>; // url → lastTs，去重
  hostDayMap: Record<string, true>;       // 今日新鲜度
  pathDayMap: Record<string, true>;
  goalProfile: {
    mode: "save" | "restraint" | "action";
    label: string;
    nextThreshold: number;
  };
  unlockedAchievements: string[];
  pendingAchievement: null | { id: string; title: string; hint: string };
};

日切：Popup / SW 启动时比较 dayKey；跨日则归档今日计数归零，累计保留，清空 hostDayMap / pathDayMap。

06

模块拆分与职责

每个模块单一职责，避免 SW 文件膨胀成上帝对象。

navigation-guard 协议白名单、内部页排除、URL 规范化、去重窗判断。
session-tracker 按 tabId 维护进行中会话；处理激活、隐藏、关闭、跳转结算。
metrics / formula 归一化与入账金额；禁止读写 storage。
ledger 追加流水、更新汇总、成就阈值（300 / 1000 / 3000 / 10000）。
repository 读写 AppState、迁移 schemaVersion、reset 全量或仅今日。
dwell-probe 可选 content script：visibilitychange + 心跳 postMessage 到 SW。
07

Popup 与交互

信息层级严格按 PRD：总额 → 最近一笔原因 → 下一成就。

Popup 结构

  • 头部品牌：网页资产计
  • 今日打开数 + 今日入账（大数字）
  • 累计资产 + 距下一成就差额
  • 最近一笔：+¥x.xx 与 reason
  • 若有 pendingAchievement：现实动作卡片 + 一键清除/稍后
  • 底部：目标模式切换入口、重置

Options（轻量）

  • 目标模式：储蓄 / 消费克制 / 行动
  • 自定义目标文案
  • 重置今日 / 重置全部（二次确认）
  • 隐私说明：本地、无上传、无正文分析
  • 预留：权重高级设置（默认隐藏）
视觉方向

与文档站一致：雾绿纸感、衬线标题、账本数字。Popup 宽度约 320–360px，动效用短促的金额淡入，不做花哨粒子。

08

权限与隐私

权限最小化；能不用 host_permissions 全站注入就不用。

storage读写本地账本
tabs读取 tab URL/title 状态，结算与排除
webNavigation可靠捕获导航完成（优先）
alarms可选：日切与会话超时兜底
scripting / host仅当需要 dwell-probe 时按需注入，MVP 可先不做
隐私红线

1. 不上传 URL 与流水。
2. 不读页面正文、不注入广告 SDK。
3. recentEntries 可只保留 host+path，去掉 query。
4. 提供一键清空所有本地数据。

09

测试与里程碑

公式与 URL 规则必须有单元测试；导航链路用手动清单 + 少量集成。

M1 · 3–5 天 骨架可跑

manifest、SW、计入/排除、固定金额 stub、Popup 读数。

M2 · 5–7 天 动态入账

四指标 + 公式 + 去重/新鲜度 + 流水与日切。

M3 · 3–4 天 成就与打磨

现实成就提示、Options、重置、样式、测试覆盖公式边界。

必测用例

  • 画像 A（PRD 示例）Score ≈ 0.836，无噪声时 deposit ≈ 8.36
  • 停留 2s 秒开列表页 → 落在约 1～2 元区间
  • 同 URL 60s 内重复打开 → 不入账
  • chrome:// 与扩展页 → 永不入账
  • 跨日 dayKey 变更 → 今日归零、累计保留
  • 累计跨过 300 / 1000 阈值 → pendingAchievement 正确
10

风险与技术决策

先钉死默认策略，避免实现期摇摆。

决策（建议锁定）

  • 平台：先 Chrome / Edge MV3，Firefox 后置
  • 构建：Vite + CRXJS 或 WXT
  • RNG：Math.random 即可；测试注入假 RNG
  • 去重窗：90s；停留采样上限：180s
  • MVP 不做 content script，停留用激活时长估算，二期再精化

主要风险

  • SW 休眠导致会话丢失 → tab 级 session 快照进 storage
  • 无 content script 时停留偏粗 → 金额略保守可接受
  • SPA 同文档路由 → 可选监听 history，MVP 可忽略以免虚增
  • 权限审核话术需强调「本地账本、非跟踪产品」
