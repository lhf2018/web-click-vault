Implemented Architecture · 0.9.0 / schema 6 · 2026-11-18

网页轻度经营 · 当前技术实现

使用 Chrome Manifest V3、原生 JavaScript 模块、HTML 和 CSS，无构建依赖。当前实现以 extension/ 为准；下方折叠区是早期技术草案，包含尚未采用的 TypeScript 路径和历史范围，不作为当前接口说明。

模块职责
background/service-worker.js导航、会话、恢复及消息编排；校验扩展页面交易来源。
content/dwell-probe.js可见停留计时、受限网页标题／站点名／主题色与代码块存在标记。
core/ledger.js浏览、任务与经营入账，独立奖励不推进浏览或重复触发装备加成。
core/market-pricing.js、market.js独立每周藏品行情、单件需求、报价校验与收购额度。
core/investments.js项目池、三周上新、小时行情、份额买卖与成本核算。
core/achievements.js54 个成就、浏览统计、进度与永久解锁同步。
storage/repository.js增量兼容、迁移快照、串行读写与成就持久化。

收藏品行情合并到 collection/；market/index.html 仅作旧入口跳转。finance/finance.js 为投资和置换提供共用界面，交易通过后台重新校验。其他经营、任务与装备模块按各自职责保留。

独立行情与份额记账

investmentCatalog(now) 返回 20 个常驻与 4 个当期项目。按 2026-01-05 UTC 起的 21 天周期生成独立项目 ID；历史项目仍可由 investmentSpec(id) 解析，持仓跨期或离线后仍可估值、卖出，新买入与加仓必须在开放期内。

investmentQuote(projectId, now) 按整点小时与项目种子生成需求、营收、成本及情绪指数，结合周期函数与日间插值扰动计算每份价格，并返回 24 小时涨跌和最多七日历史。当期项目不展示上市前价格。行情与用户行为无关，不需要定时向账本写入或调用外部行情接口。

  • investProject(state, projectId, units = 1, now)：校验整数份数、余额、开放期及 10 个持仓上限；同项目追加合并到原持仓，更新剩余本金、份额和平均成本。
  • exitProject(state, id, units = null, now)：正整数表示部分卖出，null 表示全部卖出（含旧零碎份额）；校验余量，比例分摊成本，按当前市价扣 1% 手续费。
  • 持仓字段：units 为剩余份额，活跃记录的 principal 为剩余成本，invested 为累计买入成本，returned 为累计卖出净到账，realizedProfit 为累计已实现盈亏。
  • 全部卖出后状态为 exited，份额归零，principal 保留累计投入用于历史展示；部分卖出保持 active。旧记录缺少份额时按开始时行情折算，不改变旧已结束记录。
买入成本 = round(成交价 × 买入份数, 2)
平均成本 = 剩余本金 / 剩余份数
持仓市值 = round(剩余份数 × 当前每份价格, 2)
卖出净到账 = round(round(卖出份数 × 成交价, 2) × 0.99, 2)
本次已实现盈亏 = 卖出净到账 − 本次分摊成本

investmentSpent 累计买入支出，investmentReturned 累计卖出净到账（兼容旧返本）；卖出所得不重复通过普通收入入账。总资产按现金加剩余投资市值计算，浮动盈亏不单独再次计入。份数上限 10 亿，持仓记录上限 300；加仓与部分卖出复用原记录，近期交易流水保留 50 笔。

大型项目使用独立基准每份价格 ¥1,000／¥5,000／¥10,000／¥50,000，原有项目价格模型保持不变。投资消息为 INVEST_PROJECT { projectId, units } 与 EXIT_PROJECT { id, units? }；后台缺失买入份数时拒绝，卖出省略份数时全部卖出。

藏品资产汇总采用发现时账面价值，收藏品页面展示每周市价；出售校验周标识、报价、持有状态及委托额度，原值以内转现金，只有溢价作为独立收入。

成就、数据兼容与验证

achievementStats 保存深度阅读次数、有效浏览日、最后活跃日期和最多 1,000 个归一化网站域名；仅有效浏览推进，任务与经营奖励不增加。已有总浏览、累计收益、藏品、地产、公司交付、装备等级和已卖出投资可直接计算进度。

syncAchievements 在账本结算、读取及交易保存时合并达到条件的 ID 到 unlockedAchievements。已解锁不撤销，不新增现金，原有 4 个提醒兼容。界面将 54 个里程碑与基于 SHOP_ITEMS、unlockInfo 的 9 项装备解锁合并到“探索越多，选择越多”，统一计数为 63 项，共用卡片、分类和状态筛选，不再单独渲染装备路线。

沿用 schema 6，新增默认字段增量合并。旧 schema 迁移前保存原始快照，仓库队列串行执行交易，失败不写入状态，防止并发重复出售或超卖。重置今日保留投资、成就、委托额度与经营状态；重置全部清空本地数据。数据保存在 chrome.storage.local，演示使用独立 localStorage，不连接真实扩展账本。

01

目标与范围

技术方案必须可直接对照 PRD 验收，而不是另起一套叙事。

做

  • 有效网页识别、URL 规范化、短时去重
  • 四指标采样：停留、加载、新鲜度、页面类型
  • 权重公式结算 + ±8% Noise，clamp 到 0.30～10.00
  • 今日/累计资产、最近 N 笔流水、成就阈值提示
  • 本地重置、目标模板（储蓄 / 克制 / 行动）

不做（MVP）

  • 真实支付、提现、银行对接
  • 跨设备同步、账号体系
  • 用户自定义权重（配置项预留，UI 隐藏）
  • 页面正文/DOM 内容分析、截图 OCR
  • 排行榜与社交分享

整体架构

三层：采集层 → 结算层 → 展示层；核心状态只存在 chrome.storage.local。

采集层 Visit Probe

webNavigation + tabs + PerformanceTiming / Navigation Timing；判断是否可计入。

结算层 Ledger Engine

公式纯函数 + 去重 + 新鲜度缓存 + 成就阈值检测；写流水与汇总。

展示层 Popup / Options

账本摘要、最近一笔可解释原因、目标与重置；低打扰、无复杂表格。

03

入账流水线

一次有效打开从导航到落账的完整路径。

1

导航完成

webNavigation.onCompleted 或 tabs.onUpdated（status=complete）。过滤 chrome://、edge://、about:、扩展页、devtools。

2

规范化与去重

去掉 hash、追踪参数（utm_* 等），得到 canonicalUrl。若与 recentVisits 中同 URL 间隔 < dedupeWindow（建议 90s），则丢弃。

3

开启会话采样

记录 tabId、startAt、loadMs（Navigation Timing 或 fallback）。新鲜度查今日域名/路径访问表；类型分由 URL 启发算出。

4

结算触发

优先级：tab 关闭 / 导航离开 / 文档隐藏且累计可见停留达上限（建议 180s 封顶采样）/ 用户切到其他站点。取最终 dwellMs。

5

公式入账

metrics → Score → deposit；追加 ledger 条目；更新今日/累计；若跨越成就阈值，写入 pendingAchievement。

6

展示刷新

badge 可选显示今日入账整数部分；Popup 打开时读 storage 渲染摘要与「最近一笔原因」。

04

公式引擎

必须是无副作用纯函数，便于单测与回归；Noise 注入点显式传入 RNG。

常量（对齐 PRD）

CAP10.00
MIN0.30
权重dwell 0.45 · load 0.20 · fresh 0.20 · type 0.15
NoiseUniform(−0.08, +0.08)
精度两位小数，银行家舍入或 half-up 需固定一种
接口约定

computeDeposit(scores, noise) → { score, raw, deposit, reason }
reason 用于 Popup：「停留 28s · 加载正常 · 新域名」。随机只影响 deposit，不影响 reason 文案主因排序。 

// core/formula.ts（示意）
export function computeDeposit(s: Scores, noise: number): DepositResult {
  const score =
    0.45 * s.dwell + 0.20 * s.load + 0.20 * s.fresh + 0.15 * s.type;
  const raw = CAP * score * (1 + clamp(noise, -0.08, 0.08));
  const deposit = round2(clamp(raw, MIN, CAP));
  return { score, raw, deposit, reason: buildReason(s) };
}

归一化实现要点

  • dwell：分段线性插值，与 PRD 阈值一致（3 / 15 / 60s）
  • load：<200ms 降权；200ms–2.5s 甜点；>8s 低分
  • fresh：今日 eTLD+1 首次 / 同域新路径 / 旧路径三档
  • type：正则启发（/search、/list、query 页降权）；默认 0.60

停留计量

  • 优先用 Page Visibility：仅累计 visible 时间
  • 后台标签不继续涨停留，避免虚高入账
  • 休眠唤醒后用 timestamp 差做上限裁剪
  • content script 心跳可选；无权限页则仅用 tab 事件估算
05

数据模型

全部落在 chrome.storage.local；键少、可重置、可导出（后续）。

type LedgerEntry = {
  id: string;              // uuid
  ts: number;              // 结算时间
  url: string;             // canonical，可只存 host+path
  host: string;
  amount: number;          // 0.30–10.00
  score: number;
  metrics: {
    dwellMs: number; loadMs: number;
    dwell: number; load: number; fresh: number; type: number;
  };
  reason: string;          // 展示用短句
};

type AppState = {
  schemaVersion: 1;
  dayKey: string;          // YYYY-MM-DD 本地时区
  todayVisits: number;
  todayAsset: number;
  totalVisits: number;
  totalAsset: number;
  recentEntries: LedgerEntry[];   // 最多 50
  recentVisitMap: Record<string, number>; // url → lastTs，去重
  hostDayMap: Record<string, true>;       // 今日新鲜度
  pathDayMap: Record<string, true>;
  goalProfile: {
    mode: "save" | "restraint" | "action";
    label: string;
    nextThreshold: number;
  };
  unlockedAchievements: string[];
  pendingAchievement: null | { id: string; title: string; hint: string };
};

日切：Popup / SW 启动时比较 dayKey；跨日则归档今日计数归零，累计保留，清空 hostDayMap / pathDayMap。

06

模块拆分与职责

每个模块单一职责，避免 SW 文件膨胀成上帝对象。

navigation-guard 协议白名单、内部页排除、URL 规范化、去重窗判断。
session-tracker 按 tabId 维护进行中会话；处理激活、隐藏、关闭、跳转结算。
metrics / formula 归一化与入账金额；禁止读写 storage。
ledger 追加流水、更新汇总、成就阈值（300 / 1000 / 3000 / 10000）。
repository 读写 AppState、迁移 schemaVersion、reset 全量或仅今日。
dwell-probe 可选 content script：visibilitychange + 心跳 postMessage 到 SW。
07

Popup 与交互

信息层级严格按 PRD：总额 → 最近一笔原因 → 下一成就。

Popup 结构

  • 头部品牌：网页轻度经营
  • 今日打开数 + 今日入账（大数字）
  • 累计资产 + 距下一成就差额
  • 最近一笔：+¥x.xx 与 reason
  • 若有 pendingAchievement：现实动作卡片 + 一键清除/稍后
  • 底部：目标模式切换入口、重置

Options（轻量）

  • 目标模式：储蓄 / 消费克制 / 行动
  • 自定义目标文案
  • 重置今日 / 重置全部（二次确认）
  • 隐私说明：本地、无上传、无正文分析
  • 预留：权重高级设置（默认隐藏）
视觉方向

与文档站一致：雾绿纸感、衬线标题、账本数字。Popup 宽度约 320–360px，动效用短促的金额淡入，不做花哨粒子。

08

权限与隐私

权限最小化；能不用 host_permissions 全站注入就不用。

storage读写本地账本
tabs读取 tab URL/title 状态，结算与排除
webNavigation可靠捕获导航完成（优先）
alarms可选：日切与会话超时兜底
scripting / host仅当需要 dwell-probe 时按需注入，MVP 可先不做
隐私红线

1. 不上传 URL 与流水。
2. 不读页面正文、不注入广告 SDK。
3. recentEntries 可只保留 host+path，去掉 query。
4. 提供一键清空所有本地数据。

测试与里程碑

公式与 URL 规则必须有单元测试；导航链路用手动清单 + 少量集成。

M1 · 3–5 天 骨架可跑

manifest、SW、计入/排除、固定金额 stub、Popup 读数。

M2 · 5–7 天 动态入账

四指标 + 公式 + 去重/新鲜度 + 流水与日切。

M3 · 3–4 天 成就与打磨

现实成就提示、Options、重置、样式、测试覆盖公式边界。

必测用例

  • 画像 A（PRD 示例）Score ≈ 0.836，无噪声时 deposit ≈ 8.36
  • 停留 2s 秒开列表页 → 落在约 1～2 元区间
  • 同 URL 60s 内重复打开 → 不入账
  • chrome:// 与扩展页 → 永不入账
  • 跨日 dayKey 变更 → 今日归零、累计保留
  • 累计跨过 300 / 1000 阈值 → pendingAchievement 正确
10

风险与技术决策

先钉死默认策略，避免实现期摇摆。

决策（建议锁定）

  • 平台：先 Chrome / Edge MV3，Firefox 后置
  • 构建：Vite + CRXJS 或 WXT
  • RNG：Math.random 即可；测试注入假 RNG
  • 去重窗：90s；停留采样上限：180s
  • MVP 不做 content script，停留用激活时长估算，二期再精化

主要风险

  • SW 休眠导致会话丢失 → tab 级 session 快照进 storage
  • 无 content script 时停留偏粗 → 金额略保守可接受
  • SPA 同文档路由 → 可选监听 history，MVP 可忽略以免虚增
  • 权限审核话术需强调「本地账本、非跟踪产品」
