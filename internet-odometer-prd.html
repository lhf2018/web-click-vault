01

产品定义

核心是统计有效网页打开，按多指标权重动态存入一笔钱，而不是固定单价换算。

一句话定义

网页资产计是一个浏览器插件：用户每次打开可计数的网页时，插件会采集停留、加载、新鲜度、页面类型等本地指标， 用权重公式生成一笔不超过 10 元的入账。这个数字不是抽象分数，而是可以和现实目标相连的账本单位。

核心单位
1 次有效网页打开 = 1 笔动态入账，金额由权重公式决定，单次 ≤ ¥10。
核心叙事
用户不是“刷了多少页”，而是“每一次浏览都往账本里存了一笔钱”。
产品边界
v1 先做动态记账和现实成就，不做复杂金融结算或支付闭环。
它应该更像一张会动的个人资产账，而不是固定单价的计数器。

价值感来自“这一笔为什么是这么多”：停留更久、加载更正常、域名更新鲜，入账就更高； 再往前一步，累计资产继续绑定储蓄、预算、奖励和现实里的小成就。

02

核心循环

从有效打开，到指标采样，再到动态入账与现实动作，形成一个短闭环。

  1. 识别有效网页

    浏览器打开一个可计数的网页，插件判断这是一次有效访问，而不是新标签页、刷新、内部页面或短时间重复访问。

  2. 采集四项本地指标

    在本地记录停留时长、加载耗时、域名/URL 新鲜度、页面类型启发分。不做页面正文内容分析，也不上传浏览历史。

  3. 权重公式生成入账

    四项指标归一化后加权求和，再乘以满额基准并叠加小幅随机噪声，得到一笔 ≤ ¥10 的存入。页面同时显示“打开次数”和“入账金额”。

  4. 资产映射现实并触发成就

    累计资产用于提示记账、转存、暂停冲动消费或复盘；跨过阈值时给出现实行动或金钱目标，而不是空洞徽章。

03

点击规则

这里的“点击”指有效网页打开；入账金额另由权重公式计算，不在本节省钱。

计入规则

计入 常规网页正文页，且主文档完成加载。
排除 新标签页、刷新、浏览器内部页面、扩展内部页面。
去重 同一 URL 在短时间内重复打开，不再重复入账。
结算时机 标签页关闭、切换离开，或停留达到采样窗口上限时结算该笔入账。

用户感知

不是 页面内按钮的 click 统计，不是广告事件，不是埋点面板。
是 一次有效网页打开，再按“看了多久、加载如何、是否新鲜”动态存入一笔钱。
原则 只统计用户可理解、可解释、可回忆的浏览动作；金额必须说得出为什么。
节奏 宁可少算一点、金额偏保守，也不要让数字显得虚胖。
04

权重公式

四项本地指标全部参与，归一化后加权，再加噪声，单笔封顶 ¥10。

主公式

deposit = clamp( ROUND( CAP × Score × (1 + Noise) , 2) , MIN , CAP )

其中 CAP = 10（元），MIN = 0.30（元）。
Score = 0.45·Sdwell + 0.20·Sload + 0.20·Sfresh + 0.15·Stype
Noise ~ Uniform(−0.08, +0.08)，即约 ±8% 的随机扰动，让每笔存入有“动态感”，但不喧宾夺主。

权重分配（合计 1.00）

Sdwell 停留 权重 0.45。主指标：看了才算攒到钱。
Sload 加载 权重 0.20。过快像误开，过慢像卡死，中间最优。
Sfresh 新鲜度 权重 0.20。新域名/新路径略高，短时重复已在规则层去重。
Stype 页面类型 权重 0.15。启发式区分正文页与弱内容页，不做正文分析。
设计意图：随机是装饰，指标是主因。

用户应能在 popup 里看到类似「+¥6.42 · 停留 28s · 加载正常 · 新域名」。 若去掉 Noise，同一浏览画像应得到几乎相同的金额；Noise 只负责让账本不死板。

各指标归一化（0～1）

停留 Sdwell <3s → 0.10；3–15s → 0.35～0.55；15–60s → 0.55～0.85； >60s → 0.85～1.00（分段线性插值）。结算时取最终停留。
加载 Sload 用 DOMContentLoaded 或 load 耗时。<200ms → 0.35（疑似秒开/跳转）； 200ms–2.5s → 0.70～1.00（甜点区）；2.5–8s → 0.70→0.40；>8s → 0.25。
新鲜度 Sfresh 今日首次访问该 eTLD+1 → 1.00；同域新路径 → 0.75； 今日已访问过的同路径（过了去重窗仍计入时）→ 0.40；否则 0.55。
类型 Stype http(s) 常规文档页 → 0.85～1.00；明显列表/搜索结果页启发 → 0.55； about/chrome/扩展页已排除；无法判断 → 0.60。仅用 URL 模式与导航类型，不读正文。

计算示例

画像 A 停留 28s(0.68)、加载 1.1s(0.95)、新域名(1.00)、正文页(0.90)
Score 0.45×0.68 + 0.20×0.95 + 0.20×1.00 + 0.15×0.90 = 0.836
基准额 10 × 0.836 = ¥8.36
加噪声后 例如 Noise=+0.04 → ¥8.36 × 1.04 ≈ ¥8.69（仍 ≤ 10）
画像 B 停留 2s、秒开、旧路径列表页 → Score 偏低 → 约 ¥1～¥2 区间

MVP 可把分段阈值做成常量配置；后续再允许用户微调权重，但首发建议锁死默认权重以免失控。

05

资产模型

资产值是各笔动态入账的累计；打开次数与金额成对出现，但金额不再等于次数×10。

基础账本

单笔入账 由权重公式生成，MIN～CAP，默认 0.30～10.00 元。
今日资产 今日所有有效入账之和。
累计资产 历史所有有效入账之和。
显示方式 打开次数、今日入账、最近一笔金额与原因说明成组出现。
重置逻辑 日计数可按自然日滚动；累计资产默认不清零，除非用户主动重置。
默认把“钱”当作语言，而不是承诺；把“随机”当作波动，而不是赌场。

单笔上限 10 元保留原来的心理锚点，但大多数正常浏览会落在中低区间，避免鼓励狂刷。 v1 不对接真实支付或提现，先把动态记账和成就体验做稳。

06

现实关联

资产值的意义不只是“更多”，而是能推动现实中的一个动作。

储蓄导向 默认方向

把资产值绑定到一个真实储蓄目标，比如旅行基金、电子产品基金或应急金。

  • 达到阈值后，提醒用户转入实际账户。
  • 让“网页点击”变成一笔看得见的积累。
  • 适合想把浏览习惯和理财习惯挂钩的人。
消费克制 辅助模式

当资产跨过某个阶段，就触发一次现实世界的消费检查，而不是立刻奖励自己。

  • 检查购物车、订阅和冲动消费。
  • 把浏览行为和预算纪律关联起来。
  • 更像一个温和的财务刹车。
行动导向 轻量提醒

如果用户不想谈钱，也可以把资产阈值映射成现实动作，比如记账、喝水、起身、整理桌面。

  • 让资产值成为现实动作的触发器。
  • 避免数字只在屏幕上滚动。
  • 保留钱与行为两条连接线。
07

成就系统

成就不要像任务清单，最好像一张和现实更接近的账单摘要。

开始记账

累计资产达到 ¥300。提示用户记录今天这批入账主要发生在什么浏览场景里。

守住第一笔冲动

累计资产达到 ¥1,000。建议暂停一次非必要消费，或把一笔钱从“想买”改成“先等等”。

现实动作
把钱留住

累计资产达到 ¥3,000。引导用户转入一个真实储蓄目标，哪怕只是很小的一笔。

月底有余

累计资产达到 ¥10,000。触发一次月度复盘，看看动态入账和现实开销之间发生了什么。

钱本位
从浏览到决定

当用户连续几天都把资产值用于同一个现实目标时，说明产品真的接上了生活。

看见自己的预算曲线

把入账流水做成周视图，用户能看到“网页行为”和“现实钱袋”之间的关系。

叙事感
08

展示与交互

popup 要像账本摘要：今天存了多少、最近一笔为什么、离下一个现实动作还差多少。

Popup 信息层级

第一眼看到今日入账总额，第二眼看到最近一笔与原因，第三眼看到现实动作或下一个阈值。不要把用户推进复杂表格。

第一行
今天打开：238 页 · 今日入账：¥1,246.80。
第二行
最近一笔：+¥6.42（停留 28s · 加载正常 · 新域名）。
第三行
离下一个现实成就：¥1,160。

页面气质

它应该像一张会滚动的温和账单，也像一张小型财务看板，安静、明确、略带仪式感。

视觉关键词
账本、入账流水、金额、曲线、阈值、低饱和强调色。
交互关键词
开箱即懂、低打扰、少配置、金额可解释、随时可重置目标。
默认主张
“你今天浏览的，不只是网页，也是一笔笔往账本里存的钱。”
09

MVP 边界

先把动态入账公式和现实映射做稳，再考虑可调权重或更丰富的账户玩法。

首发应做

有效打开统计、四指标采样、权重公式入账、今日/累计资产、最近一笔说明、现实成就提示、本地存储、重置入口。

首发可不做

用户自定义权重、复杂金融账户、提现、跨设备同步、排行榜、社交传播、花哨奖励动画。

后续再做

权重微调、目标账户、月度预算、储蓄计划、消费复盘、倍率模式、个人化成就模板、周/月资产摘要。

这版的关键是把“打开”变成“可解释的一笔存入”，再把“累计资产”变成“现实动作”，中间不要绕太远。
10

数据与隐私

用户愿意把网页变成钱，前提是他知道指标和流水只留在本地。

建议保存的数据

visitCount 今日打开数、累计打开数。
assetLedger 今日/累计资产；最近 N 笔入账（金额、时间、四项分、简短原因）。
metricCache 结算所需的停留、加载耗时、域名新鲜度缓存；过期即删。
recentVisits 短时间重复去重所需的最小 URL 历史。
goalProfile 用户绑定的真实储蓄目标、预算目标或现实动作模板。
隐私原则应该非常直白。

1. 本地优先，不上传完整浏览历史与入账流水。
2. 只采导航与性能类指标，不做页面正文/截图分析。
3. 真实钱目标由用户自己定义，默认不接支付。
4. 用户随时可重置打开数、资产值、流水和目标。

11

风险与开放问题

动态金额更有账本感，也更容易在公平性和可解释性上翻车。

主要风险

  • 若停留结算不准（后台标签、休眠），入账会不公平，用户很快失去信任。
  • 若权重让“狂开新站”总能接近 10 元，会诱导刷页；需用停留主权重与去重压住。
  • 随机噪声过大时，用户会觉得像抽奖而不是账本。
  • 若未来接真实资金能力，合规和安全要求会立刻上一个台阶。

待定问题

  • 默认权重 0.45/0.20/0.20/0.15 是否要在内测后微调。
  • Noise 区间 ±8% 是否合适，要不要改成固定小数抖动。
  • 同一网页隔多久再访问应重新入账；去重窗与新鲜度如何联动。
  • 现实成就是只做提醒，还是接到具体储蓄/预算工具。
  • 是否需要周报、月报和按指标拆解的资产摘要页。
