# 网页资产计 · web-click-vault

把有效网页浏览变成一笔笔本地虚拟资产，再用积累购买装备、提升收益、完成每周探索任务。

**当前版本：0.5.1** · Chrome Manifest V3 · 无需构建 · 数据保存在本机

> 所有金额都是娱乐用途的虚拟资产，不涉及充值、提现或真实投资。装备不会产生离线利息，浏览收益来自有效网页访问与结算。

## 功能概览

- **浏览入账**：根据可见停留、加载速度、新鲜度和页面类型计算基础收益，关闭标签、导航离开或达到停留上限后结算。
- **本地账本**：查看今日收益、累计收益、浏览页数、近 7 日曲线和最近流水。
- **独立增长商店**：9 件永久装备、3 个分类，支持收藏筛选、价格及常驻加成性价比排序、场景收益预览。
- **分阶段解锁**：累计收益和有效浏览页数同时达标才解锁；已拥有装备不会因新门槛重新上锁。
- **装备特效**：重访路径、探索域名、新路径和不同阅读时长可触发额外加成。
- **每周探索任务**：探索不同域名、深度阅读、跨日期保持探索，完成后领取虚拟奖励。
- **会话恢复**：异常关闭留下的会话可手动补结算，也可开启自动补结算。
- **可调设置**：SPA 路由计数、公式拆解、自动补结算，以及本地数据重置。

## 安装与更新

### 首次安装

1. 克隆仓库或下载源码并解压。
2. 在 Chrome 地址栏打开 `chrome://extensions`。
3. 开启右上角的 **开发者模式**。
4. 点击 **加载已解压的扩展程序**，选择仓库内的 **`extension` 子目录**，不是仓库根目录。
5. 从浏览器工具栏打开「网页资产计」，可将其固定到工具栏。

```bash
git clone https://github.com/lhf2018/web-click-vault.git
cd web-click-vault
```

扩展无需安装依赖、编译或启动服务器。安装时会申请网页访问权限，用于导航监听和可见停留计时。

### 更新已安装版本

1. 更新原来加载的源码目录；使用 Git 时可在仓库目录执行 `git pull --ff-only`。
2. 在 `chrome://extensions` 找到「网页资产计」，点击 **重新加载**。
3. 关闭旧的商店、设置页和弹窗，再重新打开。已打开的普通网页建议刷新，让停留探针重新连接。

**沿用原扩展目录与同一浏览器配置，不要先卸载扩展。** 扩展 ID 或浏览器配置变化后，本地数据不会自动搬迁。项目目前没有数据导入、导出或云同步功能。

旧版账本自动迁移至 schema 4，保留已有资产、历史、设置、成就和装备等级。旧购买不会补造购买历史，每周任务也不会回推旧浏览记录。

## 开始使用

1. 正常浏览 `http://` 或 `https://` 网页，停留时间按页面可见状态累计。
2. 关闭标签、导航离开，或达到 180 秒停留上限时结算。
3. 点击扩展图标查看账本，在「增长商店」卡片查看可用余额与常驻倍率。
4. 点击 **进入增长商店**，在独立标签页查看解锁进度、购买升级和领取任务奖励。
5. 点击弹窗右上角设置图标，调整计数及补结算策略。

同一规范化 URL 在约 90 秒内去重。快速反复刷新通常不会重复入账，也不会增加每周任务进度。浏览器内部页和扩展页不计入浏览收益。

## 资产与收益规则

### 余额和累计收益

```text
可用余额 = 累计收益 − 商店累计消费
```

- **累计收益**包含浏览入账与已领取任务奖励，购物不会扣减累计收益。
- **今日入账和周曲线**记录收入，不减去购物支出。
- **可用余额**用于购买装备；解锁门槛看累计收益，花钱不会使进度倒退。
- **累计浏览页数**只增加有效浏览结算次数，领取任务奖励不增加页数。
- 最近浏览及奖励流水最多保留 50 笔，日汇总保留 14 天，商店展示最近 30 次购买。

### 入账公式

```text
Score = 0.45 × 停留得分 + 0.20 × 加载得分 + 0.20 × 新鲜度得分 + 0.15 × 页面类型得分
Noise ~ Uniform(-0.08, +0.08)
基础入账 = round(clamp(10 × Score × (1 + Noise), 0.30, 10), 2)

常驻倍率 = 1 + Σ(装备等级 × 每级常驻加成)
实际倍率 = 常驻倍率 + Σ(本笔满足条件的装备等级 × 每级额外特效)
浏览入账 = round(基础入账 × 实际倍率, 2)
```

基础单次入账上限为 ¥10，装备加成后的最终入账可以超过 ¥10。所有加成相加，不相互连乘。

例如，笔记本和工作台各 1 级时，常驻倍率为 `1 + 0.10 + 0.30 = 1.40`；本笔可见停留达到 15 秒，再触发工作台的 `+0.20`，实际倍率为 `1.60`，基础 ¥5 最终入账 ¥8。

普通结算与补结算均采用**结算时**的装备等级，加成不追溯已经入账的收益。设置页可查看最近一笔浏览的基础金额、实际倍率及触发特效。

装备分为 **随身工具、效率空间、增长科技** 三类，每件最多 10 级。常驻加成始终生效，额外特效在对应条件满足时叠加。

| 星际传送门 | ¥20,000 | +1,000% | ×2.20 | 当日首次探索域名 +1,000% |

```text
下一级价格 = round(首级价格 × 升级价格系数 ^ 当前等级, 2)
```

“首次域名”“新路径”“重访路径”按当日有效结算记录判断。某域名当日首次结算归为首次域名，之后的未见路径归为新路径，已见路径归为重访路径。它们是互斥的新鲜度类别；阅读时长特效则可与新鲜度特效同时触发。

## 每周探索任务

任务以**浏览器本地时间的周一**为一周起点，在下一次读取账本或结算时刷新。进度从支持任务的版本开始记录，不回推历史；补结算计入实际结算所在周和日期。

| 任务 | 完成条件 | 奖励 |
| --- | --- | ---: |
| 探索新视野 | 本周浏览 5 个不同域名，每个可见停留至少 15 秒 | ¥100 |
| 沉浸阅读者 | 本周完成 5 次可见停留至少 60 秒的有效浏览 | ¥150 |
| 保持好奇心 | 本周在 3 个不同日期各完成一次至少 15 秒的有效浏览 | ¥200 |

- 在商店页面点击 **领取奖励**，每个任务每周只能领取一次。
- **必须在本周领取**；下周刷新时，旧进度和未领取奖励清空。
- 奖励计入余额、今日入账、累计收益和收入流水，可推动累计收益成就与装备解锁。
- 奖励不享受装备加成、不增加浏览次数，也不会推进任务本身。
- 单次有效浏览可以同时推进多个任务；域名任务按主机名去重，并将 `www.` 前缀归一化。

## 设置与会话恢复

| 设置 | 默认值 | 行为 |
| --- | --- | --- |
| 计入 SPA / History 路由 | 关闭 | 开启后，同文档的路径切换也参与结算和新会话记录 |
| 显示公式拆解 | 开启 | 在设置页展示最近一笔浏览的得分、噪声、倍率和特效 |
| 自动补结算 | 关闭 | 自动处理异常关闭或扩展重启留下的待结算会话 |

开启自动补结算时，会立即处理当前待补结算记录；之后启动及定期扫描发现的异常会话也会自动处理。关闭时，弹窗保留 **补结算 / 丢弃** 选择。补结算继续遵守 URL 去重规则。

**重置今日**保留累计收益、装备、消费和每周任务进度；**重置全部数据**会清空本地账本、装备、任务和会话，无法撤销。

## 隐私与权限

扩展通过 `chrome.storage.local` 保存资产、装备、任务进度、近期 URL / 域名和会话信息。不读取网页正文，不向服务器上传浏览记录；数据不跨设备同步。

| 权限 | 用途 |
| --- | --- |
| `storage` | 保存本地账本、设置与会话 |
| `tabs`、`windows` | 跟踪标签、窗口与当前会话状态 |
| `webNavigation` | 感知页面导航与可选的 SPA 路由切换 |
| `alarms` | 定期结算、日期检查与异常会话扫描 |
| `http://*/*`、`https://*/*` | 注入可见停留计时探针 |

## 常见问题

**更新后看不到商店或新设置？** 仅刷新设置页不足以更新后台。请先在 `chrome://extensions` 重新加载扩展，再关闭旧页面并重新打开。

**自动补结算勾选后又取消，或显示后台版本过旧？** 按上面的步骤重新加载扩展与设置页；正常保存后会显示“设置已保存”。

**有余额为什么还买不了？** 余额、解锁条件与满级限制分别校验。查看商品提示，确认累计收益和浏览页数均达标。

**为什么没有立刻涨钱或增加任务进度？** 账本和任务在有效结算后更新，后台标签不持续增加可见停留。快速重复访问还可能被 90 秒去重规则过滤。

**为什么倍率与商品卡预览不同？** 概况显示常驻倍率；场景预览还会加上满足条件的特效。最终金额取决于本笔基础得分、噪声和结算时装备等级。
